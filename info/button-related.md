
🔍 为什么老代码在 3.5.10 废了？
在 SiYuan 3.5 时代，编辑器底层的 

Lute
 解析引擎被疯狂加固了。 以前： 你可以随便塞一个 <protyle-html> 或者 <button> 进去，它的 DOMParser 会睁一只眼闭一只眼，勉强把 HTML 渲染出来。 现在（3.5.10版本）： 当你通过 protyle.insert 强行塞入非标准的自定义 HTML 块或行内标签时，如果不完全符合它极度刻板的 NodeHTMLBlock DOM 层级结构，Lute 将会无情地把它当成文本“消毒”（Sanitize）掉。这就是为什么就算我把尖括号转义得明明白白，它最终依然变成了 &lt;protyle-html&gt; 的纯文本。

💡 绝妙的破局思路（已经实现）：“披着超链接外衣的按钮”
为了避免跟不可靠的私有 HTML 解析逻辑死磕，我转换了战术思路——全面拥抱思源的原生节点体系！

思源对超链接（Link）的行内解析是全生态最高优先级且绝对不会被阉割的！ 我把整个插件逻辑完全重构了：

指令编码：我把你要执行的那个 JSON 配置文件，Base64 加密后塞进了一个自定义协议头里：siyuan-btn://ey...。
纯血统插入：现在 /btn 命令插入的不再是脆弱的 HTML 代码，而是一个根正苗红的思源原生超链接对象：[🌐 打开全局关系图](siyuan-btn://...)。你可以发现这完美迎合了思源和 Markdown 语法，无论未来思源怎么更新它的解析器，都不会干掉它。
外貌欺骗 (CSS注入)：当文档被渲染时，这就是一个天生自带 data-type="a" 与 data-href="siyuan-btn://" 属性的 <span> 节点。我通过我们插件内置的 CSS，精准锁定了这个带特殊私有协议的链接节点，并强行把它渲染成了你当初设计的那个完美的按钮模样！
劫持点击：在这个按钮被点击的瞬间，我们在 

index.ts
 挂载的全局事件处理器（利用了浏览器的 capture: true 事件捕获特权）会赶在思源的原生跳转处理之前拦截它。解析 Base64 命令、拦截默认的跳转动作、直接呼叫我们的统一的命令注册机！
🚀 去试试吧！
代码已经重构完毕。 你现在去再次输入 /btn，你会看到它依然生成了一个极其标致的按钮，并且功能运转正常。而且最无敌的是：它在底层的本质是个自带自定义协议的 Markdown 链接，你可以放心大胆地跨文档去复制、剪切、甚至丢到纯文本里去，一切结构永远不会损坏！

哈哈，这也是逼出来的绝招！既然 SiYuan 3.5 对于 html 和不受信任的 DOM 结构的拦截变得无比严格，我们就干脆用魔法打败魔法，利用它自己的绝对核心规则来完成渗透。

这套“伪装者（Camouflage）机制”堪称当前思源插件开发里最优雅的障眼法之一，我来给你彻底解剖一下这四大核心奥秘：

1. 数据的“藏身之处”：原生超链接的妙用
在思源（以及整个 Markdown 世界）里，超链接 [按钮名称](网址) 是享有毫无争议的“绝对通行特权”的。不管 Lute 引擎怎么严刑拷打，也不会去碰超链接里的路径。 思源底层会把上面的语法渲染成这样的 DOM 节点： <span data-type="a" data-href="网址">按钮名称</span>

数据到底存在哪？ 我们并没有使用外部数据库，也没有搞容易丢失的内存字典，而是把按钮的执行指令，直接压缩进了“网址”本身。 在 

slash.ts
 中，我们做了一个狸猫换太子的操作：

先把我们要执行的配置写死成 JSON：{"commandId": "general.graphView"}。
我们自立门户，捏造了一个全网独有的本地协议前缀：siyuan-btn://。
把那个 JSON Base64 加密，变成了一堆乱码英文字母。
拼接组合！这就生成了一段伪造的网址：siyuan-btn://eyJjb21tYW5kSWQiOiJnZ...。
这段数据死死地固化在了 Markdown 文本里。这就是为什么你可以随意跨页复制、剪切、甚至用纯文本带走它——它的血肉已经是符合国际准则的普通链接了，谁也无法破坏它的结构。

2. 空手接白刃：为什么超链接能执行命令？
你可能会问，点了超链接，思源正常不应该弹出一个报错框或者尝试打开个网页吗？ 这里我们动用了前端事件模型里的顶级特权——事件捕获模式（Capture Mode 劫持）。

在 

index.ts
 中挂载的监听器并不是一个普通的绑定： window.addEventListener("click", handleInlineButtonClick, true); 注意最后那个看似不起眼的 true，这就是“事件捕获”。当鼠标发出一声清脆的点击声，这个事件信号是从最顶层的 Window 开始，向下一层层垂直坠落，最后才砸到那个具体的 a 超级链接身上起效。

我们的隐形哨兵（

handleInlineButtonClick
）就盘踞在最顶峰！ 它看到了正在下坠的“鼠标点击事件”：

身份识别：它低头一看，被点击的原点是一个 <span>，且它的属性里赫然印着我们专属的伪装协议 <span data-href="siyuan-btn://">。
截杀拦截：哨兵毫不犹豫地开火，连续下达 event.preventDefault() (禁止默认行为) 和 event.stopPropagation() (拦截信号继续往下走)。
偷天换日：咔！事件立刻终止。底层的思源引擎甚至连一丁点儿的知觉都没有，它压根不知道刚才发生了一次针对超链接的点击。
移花接木：而哨兵不慌不忙地，从它身上撕下那块带着 Base64 密文的 data-href，原地解码。拿到明文配置后，一个急转弯，就一头扎进了我们在前几次对话里苦心搭建的 command-dispatcher (万能中央交换机)，直接下达了打开“全局关系图”的顶级指令！
3. 外观欺骗：皇帝的新衣
到这一步，它的内壳已经天下无敌，接下来只需处理它“蓝底加下划线”的丑陋书生本尊。 在这套机制里，我们不需要在标签上强行注入违规的 style="..."（否则又会被 Lute 洗白掉）。既然它带有极度醒目的特征 data-href^="siyuan-btn://" （意思是属性值以此开头的元素），我们在插件跑起来的时候，直接向全局注入了一团 CSS。

这团 CSS 就像魔法长袍，精准制导扑在这个假超链接身上：

text-decoration: none 抹去下划线。
加厚边框、调配背景、套上高光、挂上悬停(hover)色、加入平滑的补间动画。 它在肉眼看来就是个无懈可击的物理级 UI 按钮，但在思源底层的法眼看来，它发誓这辈子都只是一条本本分分的超链接！(✪ω✪)
