# 思源笔记插件：块级精度表格与数据拓扑设计思考

## 1. 核心架构：关注点分离 (Separation of Concerns)

基于对当前 `list/action.ts` 和 `attribute-view` 代码的深入分析，我们明确了以下三层的职责划分：

| 维度 | 职责 | 来源 (SOT) | 插件角色 |
| :--- | :--- | :--- | :--- |
| **逻辑层 (Database)** | 属性管理、过滤、聚合 | 思源 Attribute View (AV) | 存储中枢 |
| **层级层 (List)** | 父子关系、深度、路径 | NodeList (树状结构) | 提供 `Father`, `Level`, `Path` |
| **位置层 (Table)** | 网格坐标、二维排布 | Custom Grid (二维结构) | 提供 `Row`, `Col`, `Coordinate` |

### 结论：是否可能且有必要？
**完全可能，且极具架构意义。**
当前的“列表同步”是将**一维/嵌套结构**索引到数据库。未来的“表格同步”是将**二维位置信息**索引到数据库。这种表格不再仅仅是渲染，而是作为一种特殊的**输入和组织协议**。

---

## 2. 表格设计：作为位置信息的 SOT (Source Of Truth)

### 2.1 表头设计 (Headers)
- **顶部 Header (列轴)：** 通常代表数据库的一个 **“显性属性 (Attribute)”**（如：状态、优先级、负责人）。
- **左侧 Header (行轴)：** 通常代表数据库的一个 **“实体/容器 (Entity/Container)”**（如：所属项目、时间段、特定分类）。
- **交叉点 (Cell)：** 存放具体的块（Block）。

### 2.2 块的拖拽替换与属性联动
- **拖拽即更新逻辑：** 当一个块从 `(Row A, Col 1)` 移动到 `(Row A, Col 2)` 时，插件应自动识别：
    - 该块关联的 AV Item。
    - 列 1 对应的属性值 A。
    - 列 2 对应的属性值 B。
    - **自动执行：** `batchSetAttributeViewBlockAttrs` 将属性由 A 更新为 B。
- **拖拽即管理：** 表格成为了数据库的**可视化编辑器**。

---

## 3. 功能拓扑：我们能支持什么？

通过“表格位置反向映射到数据库属性”，这种设计能支持极强的批量管理功能：

1.  **矩阵式看板 (Matrix Kanban)：** 
    - 比传统看板多了一个维度。例如：X轴是状态，Y轴是优先级。将任务放入某个格子里，它就同时具备了这两个维度的属性。
2.  **可视化排程 (Visual Scheduling)：**
    - X轴是星期，Y轴是时间段。拖入块即完成预约，数据库自动更新时间字段。
3.  **结构化对比 (Structured Comparison)：**
    - 左侧是产品 A/B，顶端是性能/价格。每个单元格是一个详细说明块。这使得非结构化信息（长文块）具备了结构化定位。
4.  **知识地图栅格 (Knowledge Grid)：**
    - 实现类似“九宫格知识法”或“曼陀罗思考法”的数据录入，将灵感位置固定化并存入数据库。

---

## 4. 这种表格像什么？

它不再像传统的 SQL 扁平表，它更接近以下概念：

*   **视觉化索引 (Visual Indexer)：** 像图书馆的索引卡片架，位置本身就是信息。
*   **Heptabase 或 Miro 的栅格化增强版：** 它具备白板的视觉位置，却拥有数据库的严谨内核。
*   **多维透视表的前端代理 (Frontend Proxy for Pivot Tables)：** 
    *   在传统的 Excel 里，透视表是“读”的结果。
    *   这种设计里，表格是“写”的手段。你摆弄表格，实际上是在重塑后台的数据透视。

### 核心比喻：**“空间化的数据库网格”**
如果列表是“线”，数据库是“点”，那么这个插件表格就是“面”。它通过“空间排布”来自动生成和管理数据库中那些枯燥的属性标签。

---

## 5. 实现关键点 (基于 action.ts 经验)

1.  **位置解析：** 仿照 `traverseWithContext` 解析列表 Path 的逻辑，编写 `parseGridPosition` 解析表格坐标。
2.  **双向绑定：** 保证表格中的格子与数据库 Row/Col UUID 之间有一一对应的映射。
3.  **属性拦截：** 当表格 DOM 发生变化（如拖拽移动项）时，拦截事件并转化为 `doOperations` 或 `api/av/batchSetAttributeViewBlockAttrs` 调用。
